Troubleshooting · DeepSeek tool calls

修复 Raycast 中的“reasoning_content must be passed back”。

当 DeepSeek thinking-mode tool call 后的下一次 request 缺少前一次 model 输出的 reasoning_content 时，就会出现这一错误。Raycast 当前不会回放这个 provider-specific field。

问题是怎样发生的

1. DeepSeek reasoning 后调用 tool

Model response 同时包含 tool call 与 provider 要求的 reasoning_content。

2. Raycast 执行 tool

Raycast 在下一次 Chat Completions request 中发送 tool result，但不包含前一次 DeepSeek reasoning 字段。

3. DeepSeek 拒绝继续

缺少必要 reasoning state 时，provider 无法验证 thinking-mode tool turn。

APIdapter 的修复方式 APIdapter 只捕获协议必需的 reasoning state，在受限内存中保存，并在下一次 request 中把它附加到匹配的 assistant tool-call message。

修复步骤

  1. 打开 Raycast chat 前先启动 APIdapter。检查 http://127.0.0.1:48765/healthz。
  2. 把 APIdapter 设置为 Raycast base URL。直接请求 DeepSeek 会绕过 state repair。
  3. 在整个 tool loop 期间保持 APIdapter 运行。重启会清空 in-memory reasoning state。
  4. 重启后新建 chat。旧会话可能仍在引用已经不存在的 state。

如果 APIdapter 返回 reasoning_state_missing

匹配 state 可能因为 daemon 重启、TTL 到期或容量限制被清除。这是刻意的安全边界：APIdapter 不会把 conversation state 持久化到磁盘。
