Troubleshooting · DeepSeek tool calls

Fix “reasoning_content must be passed back” in Raycast.

The error appears when a DeepSeek thinking-mode tool call is followed by another request that omits the model's earlier reasoning_content. Raycast currently does not replay that provider-specific field.

What is happening

1. DeepSeek reasons and calls a tool

The model response contains both a tool call and provider-required reasoning_content.

2. Raycast runs the tool

Raycast sends the tool result in the next Chat Completions request, but does not include the earlier DeepSeek reasoning field.

3. DeepSeek rejects the continuation

The provider cannot validate the thinking-mode tool turn without the required reasoning state.

APIdapter's repair APIdapter captures only the required reasoning state, keeps it in bounded memory, and attaches it to the matching assistant tool-call message on the next request.

How to fix it

  1. Start APIdapter before opening the Raycast chat. Verify http://127.0.0.1:48765/healthz.
  2. Use APIdapter as Raycast's base URL. A direct request to DeepSeek bypasses the state repair.
  3. Keep APIdapter running for the whole tool loop. Restarting it clears the in-memory reasoning state.
  4. Start a new chat after a restart. An old conversation can refer to state that no longer exists.

If APIdapter returns reasoning_state_missing

The matching state was cleared because the daemon restarted, the configured TTL expired, or a capacity bound evicted it. This is intentional: APIdapter does not persist conversation state to disk.
